SECTION 1: AI MODEL TRAINING COMPUTE SCALING FORMULAS
================================================================================

1.1. THEORETICAL TRAINING FLOPS (KAPLAN & CHINCHILLA SCALING LAW)
--------------------------------------------------------------------------------
FORMULA:
    FLOPs_total = 6 * N * D

HOW THIS FORMULA WORKS:
    In deep learning, training a Transformer model requires computing billions of
    matrix multiplications for every single token of text. The empirical scaling
    research established by OpenAI (Kaplan et al.) and DeepMind (Chinchilla paper)
    proves that standard autoregressive Transformer training scales predictably
    as a linear function of model parameter count (N) and dataset tokens (D).

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [FLOPs_total]: Floating-Point Operations.
      - WHAT IT DOES: Represents the total cumulative floating-point math operations
        (additions and multiplications) required to complete the training run.
      - UNIT: Raw FLOPs (typically 10^21 ZettaFLOPs or 10^24 YottaFLOPs).

    * [6]: Empirical Constant Multiplier.
      - WHAT IT DOES: Accounts for both the forward and backward training passes.
      - BREAKDOWN:
        -> 2 FLOPs per parameter per token during the FORWARD pass:
           For each weight in a linear layer, calculating y = W*x requires 1 multiply
           and 1 add (1 Multiply-Accumulate = 2 FLOPs).
        -> 4 FLOPs per parameter per token during the BACKWARD pass:
           The backward pass computes two sets of gradients:
           1) Gradient of loss with respect to inputs (dL/dx): 2 FLOPs
           2) Gradient of loss with respect to weights (dL/dW): 2 FLOPs
        -> Total = 2 (forward) + 4 (backward) = 6 FLOPs per parameter per token.

    * [N]: Model Parameter Size.
      - WHAT IT DOES: The total number of trainable weights, biases, and embedding
        matrices in the neural network architecture.
      - UNIT: Integer count (e.g., 70 Billion parameters = 70 * 10^9).

    * [D]: Training Dataset Size.
      - WHAT IT DOES: The total volume of tokenized text sequences processed across
        all training epochs.
      - UNIT: Token count (e.g., 300 Billion tokens = 300 * 10^9).

WORKED NUMERICAL EXAMPLE:
    For Llama-2 / Qwen 70B trained on 300 Billion tokens:
        N = 70 * 10^9
        D = 300 * 10^9
        FLOPs_total = 6 * (70 * 10^9) * (300 * 10^9)
                    = 6 * 2.1 * 10^22
                    = 1.26 * 10^23 FLOPs (0.126 YottaFLOPs / 126 ZettaFLOPs)

1.2. TARGET COMPUTE THROUGHPUT (TFLOPS REQUIRED)
--------------------------------------------------------------------------------
FORMULA:
    TFLOPs_target = FLOPs_total / ( T_seconds * 10^12 )
    where:
    T_seconds = Target_Days * 24 * 3600

HOW THIS FORMULA WORKS:
    This formula converts the astronomical number of raw total training FLOPs into
    a steady-state compute speed (Throughput per second) needed to complete the run
    before a scheduled deadline.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [TFLOPs_target]: Target TeraFLOPs per second.
      - WHAT IT DOES: The continuous computation rate the entire cluster must sustain
        every second without interruption to meet the delivery timeline.
      - UNIT: TeraFLOPs/sec (10^12 FLOPs/sec).

    * [FLOPs_total]: The numerator computed from Section 1.1 (e.g., 1.26 * 10^23).

    * [T_seconds]: Total Available Time Window.
      - WHAT IT DOES: Converts calendar days into raw seconds available for training.
      - BREAKDOWN: Target_Days * 24 hours/day * 3600 seconds/hour = Target_Days * 86,400.

    * [10^12]: Metric Conversion Divisor.
      - WHAT IT DOES: Converts raw FLOPs into TeraFLOPs (1 TeraFLOP = 10^12 FLOPs).

WORKED NUMERICAL EXAMPLE:
    Target Deadline = 14 Days:
        T_seconds     = 14 * 86,400 = 1,209,600 seconds
        TFLOPs_target = (1.26 * 10^23) / (1,209,600 * 10^12)
                      = 104,166.67 TFLOPs (or 104.17 PetaFLOPs steady-state)

SECTION 2: HARDWARE CLUSTER SIZING & MFU FORMULAS
================================================================================

2.1. HARDWARE GPU CARDS REQUIRED AT MFU EFFICIENCY
--------------------------------------------------------------------------------
FORMULA:
    GPUs_needed = ceil( TFLOPs_target / ( GPU_peak_TFLOPs * MFU ) )

HOW THIS FORMULA WORKS:
    In physical data centers, GPUs never achieve 100% of the peak TFLOPs printed on
    the manufacturer spec sheet. Memory bandwidth limits (HBM3), kernel launch
    overheads, and network gradient synchronization (AllReduce) reduce real-world
    compute speed. This formula sizes the physical hardware fleet while accounting
    for real-world operational efficiency (MFU).

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [GPUs_needed]: Total Discrete Physical Accelerators.
      - WHAT IT DOES: The minimum number of GPU cards required to reach throughput.
      - UNIT: Count of GPU chips (integer).

    * [ceil(...) ]: Ceiling Mathematical Function.
      - WHAT IT DOES: Rounds fractions UP to the nearest whole integer, because you
        cannot purchase or provision a fraction of a physical GPU card.

    * [TFLOPs_target]: Sustained throughput required from Section 1.2 (e.g., 104,166 TFLOPs).

    * [GPU_peak_TFLOPs]: Manufacturer Peak Hardware Specification.
      - WHAT IT DOES: The maximum theoretical FP16/BF16 matrix speed of 1 accelerator.
      - SPECIFICATIONS REFERENCE:
        -> NVIDIA H100 SXM5: 350 TFLOPs dense FP16 (700W TDP, ~$30,000)
        -> NVIDIA A100 SXM4: 156 TFLOPs dense FP16 (400W TDP, ~$10,000)
        -> NVIDIA L40S PCIe:  91 TFLOPs dense FP16 (350W TDP,  ~$7,000)

    * [MFU]: Model FLOPs Utilization.
      - WHAT IT DOES: Efficiency coefficient representing the ratio of actual time
        spent executing matrix multiplications versus waiting for data/networking.
      - VALUE: Typically 0.30 to 0.35 (30% to 35% efficiency in production).

WORKED NUMERICAL EXAMPLE:
    Using NVIDIA H100 (350 TFLOPs peak, 30% MFU):
        Effective Throughput per GPU = 350 * 0.30 = 105 TFLOPs
        GPUs_needed = ceil( 104,166.67 / 105 )
                    = ceil( 992.06 ) = 993 GPUs


--------------------------------------------------------------------------------
2.2. SERVER CABINET ALLOCATION (8-GPU NODES)
--------------------------------------------------------------------------------
FORMULA:
    Servers_needed = ceil( GPUs_needed / 8 )
    GPUs_allocated = Servers_needed * 8

HOW THIS FORMULA WORKS:
    Enterprise AI accelerators are packaged into standardized rackmount server nodes
    containing exactly 8 GPUs connected via high-speed NVLink switches (e.g., HGX H100).
    Clusters must be provisioned in multiples of whole server nodes.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [Servers_needed]: Number of physical server cabinets (chassis).
    * [8]: Standard number of GPUs per AI server chassis (NVLink backplane topology).
    * [GPUs_allocated]: The actual integer count of GPUs deployed in the fleet.

WORKED NUMERICAL EXAMPLE:
    Servers_needed = ceil( 993 / 8 ) = ceil( 124.125 ) = 125 Server Cabinets
    GPUs_allocated = 125 * 8 = 1,000 GPUs

SECTION 3: SERVER POWER & ELECTRICITY CONSUMPTION FORMULAS
================================================================================

3.1. TOTAL CLUSTER / SERVER POWER DRAW (kW)
--------------------------------------------------------------------------------
FORMULA:
    P_cluster (kW) = [ ( GPUs_allocated * GPU_TDP_Watts ) + ( Servers * P_aux ) ] / 1000

HOW THIS FORMULA WORKS:
    Calculates the total continuous electricity demand drawn from the electrical grid
    or power distribution unit (PDU). It accounts for both the silicon GPU compute
    dissipation and the non-GPU host hardware.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [P_cluster]: Total electrical power required to operate the computing cluster.
      - UNIT: Kilowatts (kW).

    * [GPUs_allocated * GPU_TDP_Watts]: Total Silicon Compute Load.
      - WHAT IT DOES: Multiplies total GPUs by their Thermal Design Power (TDP).
      - TDP: The maximum heat/power the chip can dissipate under continuous load
        (e.g., 1,000 H100s * 700W = 700,000 Watts).

    * [Servers * P_aux]: Server Auxiliary Overhead Load.
      - WHAT IT DOES: Accounts for all essential host motherboard hardware:
        dual AMD EPYC host CPUs, 2TB DDR5 RAM, NVMe storage drives, PCIe gen 5 switches,
        ConnectX-7 InfiniBand NICs, internal fans, and pump VRMs.
      - VALUE: ~450 Watts per 8-GPU chassis (or ~180W on single-workstation V-GPU).

    * [1000]: Electrical Unit Divisor.
      - WHAT IT DOES: Converts raw Watts into Kilowatts (1 kW = 1000 Watts).

WORKED NUMERICAL EXAMPLE:
    1,000 H100 GPUs across 125 Cabinets:
        P_gpus = 1,000 * 700W = 700,000 Watts
        P_aux  = 125 * 450W   =  56,250 Watts
        P_cluster = (700,000 + 56,250) / 1000 = 756.25 kW


--------------------------------------------------------------------------------
3.2. TOTAL LIFECYCLE TRAINING ENERGY CONSUMPTION (MWh)
--------------------------------------------------------------------------------
FORMULA:
    Energy_total (MWh) = ( P_cluster (kW) * Target_Days * 24 ) / 1000

HOW THIS FORMULA WORKS:
    Energy is power integrated over time (Work = Power * Time). This calculates the
    total electricity bill and power plant generation needed for the entire training run.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [Energy_total]: Total cumulative electrical energy consumed.
      - UNIT: Megawatt-hours (MWh).

    * [P_cluster]: Continuous cluster power draw in kW from Section 3.1.
    * [Target_Days * 24]: Total continuous operational hours (e.g., 14 days * 24 = 336 hours).
    * [1000]: Metric conversion from Kilowatt-hours (kWh) to Megawatt-hours (MWh).

WORKED NUMERICAL EXAMPLE:
    Energy_total = ( 756.25 kW * 14 * 24 ) / 1000
                 = ( 756.25 * 336 ) / 1000
                 = 254.10 MWh (254,100 kWh)


--------------------------------------------------------------------------------
3.3. ENVIRONMENTAL CARBON FOOTPRINT EMISSIONS
--------------------------------------------------------------------------------
FORMULA:
    Carbon_kg_CO2e = Energy_kWh * Grid_Emission_Factor
    where:
    Energy_kWh = Energy_total (MWh) * 1000

HOW THIS FORMULA WORKS:
    Converts electrical energy consumption into equivalent greenhouse gas mass (CO2e)
    released into the atmosphere by electricity generation utility plants.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [Carbon_kg_CO2e]: Kilograms of Carbon Dioxide equivalent emitted.
    * [Grid_Emission_Factor]: Carbon intensity of electricity supply.
      - VALUE: 0.385 kg CO2e / kWh (standard global data center grid blend).

WORKED NUMERICAL EXAMPLE:
    Carbon_kg_CO2e = 254,100 kWh * 0.385 kg/kWh
                   = 97,828.5 kg CO2e (~97.8 metric tons of CO2)

SECTION 4: THERMODYNAMIC WATER COOLING & ENVIRONMENTAL METRICS
================================================================================

4.1. DYNAMIC WATER USAGE EFFECTIVENESS (WUE)
--------------------------------------------------------------------------------
FORMULA:
    WUE_effective = WUE_baseline + Delta_WUE_thermal

HOW THIS FORMULA WORKS:
    Water Usage Effectiveness (WUE) is an international ISO/IEC standard data center
    efficiency metric. It defines how many liters of water are evaporated or consumed
    to cool 1 kilowatt-hour of IT hardware energy. Hotter chips evaporate water faster,
    so this formula dynamically applies a thermal efficiency penalty.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [WUE_effective]: Net dynamic water consumption coefficient.
      - UNIT: Liters per Kilowatt-hour (L/kWh).

    * [WUE_baseline]: Nominal cooling infrastructure rating:
      - VALUE: 0.280 L/kWh for Closed-Loop Liquid Direct-to-Chip cooling.
      - VALUE: 0.450 L/kWh for Traditional Evaporative Air Cooling Towers.

    * [Delta_WUE_thermal]: Temperature Degradation Penalty:
      - WHAT IT DOES: When GPU silicon exceeds 70°C, cooling tower heat exchangers
        must increase evaporative cooling spray volume to prevent thermal shutdown.
      - CONDITIONAL LOGIC:
        If max(GPU_temperature) > 70.0°C: Delta_WUE_thermal = +0.050 L/kWh
        If max(GPU_temperature) <= 70.0°C: Delta_WUE_thermal = 0.000 L/kWh

WORKED NUMERICAL EXAMPLE:
    Under optimal cooling (T <= 70°C):
        WUE_effective = 0.280 + 0.000 = 0.280 L/kWh
    Under thermal stress (T > 70°C):
        WUE_effective = 0.280 + 0.050 = 0.330 L/kWh


--------------------------------------------------------------------------------
4.2. HOURLY WATER CONSUMPTION RATE (LITERS / HOUR)
--------------------------------------------------------------------------------
FORMULA:
    Water_Rate (L/hr) = P_cluster (kW) * WUE_effective (L/kWh)

HOW THIS FORMULA WORKS:
    Multiplies real-time electricity draw by the water consumption coefficient
    to determine the rate at which cooling towers consume municipal water.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [Water_Rate]: Water volume lost to evaporation each hour.
      - UNIT: Liters per Hour (L/hr).
    * [P_cluster]: Real-time total power draw in kW (Section 3.1).
    * [WUE_effective]: Effective WUE in L/kWh (Section 4.1).

WORKED NUMERICAL EXAMPLE:
    Cluster power = 756.25 kW at baseline WUE = 0.280 L/kWh:
        Water_Rate = 756.25 kW * 0.280 L/kWh
                   = 211.75 Liters / hour (approx. 5,082 Liters per day)


--------------------------------------------------------------------------------
4.3. CHILLER COOLANT CIRCULATION FLOW RATE (LITERS / MINUTE)
--------------------------------------------------------------------------------
FORMULA:
    Flow_chiller (L/min) = P_cluster (kW) * 1.5 * eta_loop

HOW THIS FORMULA WORKS:
    Based on the specific heat capacity of water (4.184 J/g°C), dissipating 1 kW
    of thermal energy with a 10°C temperature delta across liquid cold plates requires
    a volumetric flow rate of approximately 1.5 Liters per minute per kW.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [Flow_chiller]: Volumetric coolant pumped through cold plates and manifolds.
      - UNIT: Liters per Minute (L/min).
    * [1.5]: Thermodynamic specific heat constant for a 10°C coolant loop delta (dT).
    * [eta_loop]: Plumbing Hydraulic Efficiency Factor:
      - VALUE: 1.2 for Direct-to-Chip microchannel liquid loops.
      - VALUE: 0.8 for Air-cooled heat-pipe manifolds.

WORKED NUMERICAL EXAMPLE:
    Cluster power = 756.25 kW (Liquid loop eta = 1.2):
        Flow_chiller = 756.25 * 1.5 * 1.2
                     = 1,361.25 Liters / minute


--------------------------------------------------------------------------------
4.4. EVAPORATIVE LOSS & RECIRCULATED COOLANT RATES
--------------------------------------------------------------------------------
FORMULAS:
    Loss_evaporative (L/hr)   = Water_Rate (L/hr) * 0.95
    Water_recirculated (L/hr) = ( Flow_chiller * 60 ) - Loss_evaporative

HOW THIS FORMULA WORKS:
    Cooling towers cool warm water by evaporating ~95% of the heat dissipation volume
    to the open atmosphere. The remaining coolant is recirculated through the primary loop.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [0.95]: Evaporation fraction in standard forced-draft cooling towers (95%).
    * [Flow_chiller * 60]: Converts Liters/min of chiller pump flow into Liters/hour.
    * [Water_recirculated]: Coolant volume filtered and pumped back into servers.

WORKED NUMERICAL EXAMPLE:
    Loss_evaporative   = 211.75 * 0.95 = 201.16 Liters / hour
    Total pump volume  = 1,361.25 * 60 = 81,675.00 Liters / hour
    Water_recirculated = 81,675.00 - 201.16 = 81,473.84 Liters / hour


--------------------------------------------------------------------------------
4.5. TOTAL LIFECYCLE TRAINING WATER FOOTPRINT (LITERS)
--------------------------------------------------------------------------------
FORMULA:
    Water_total (Liters) = ( Energy_total (MWh) * 1000 ) * WUE_effective

HOW THIS FORMULA WORKS:
    Integrates the entire training duration to calculate the total cumulative
    water volume consumed from dataset token 1 to the final epoch checkpoint.

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [Water_total]: Grand total liters of water consumed by the AI model.
    * [Energy_total * 1000]: Converts MWh to kWh (e.g., 254.10 * 1000 = 254,100 kWh).
    * [WUE_effective]: 0.280 L/kWh.

WORKED NUMERICAL EXAMPLE:
    Water_total = 254,100 kWh * 0.280 L/kWh
                = 71,148 Liters (equivalent to ~71.1 metric tons of water)

SECTION 5: PARALLEL SCALING & NETWORK LOSS (AMDAHL'S LAW)
================================================================================

5.1. AMDAHL'S LAW WITH ALLREDUCE NETWORK SCALING BARRIER
--------------------------------------------------------------------------------
FORMULA:
    Speedup(N) = 1 / [ ( 1 - P ) + ( P / N ) + Comm_Penalty(N) ]
    where:
    Comm_Penalty(N) = 0.0012 * N^(1.25)

HOW THIS FORMULA WORKS:
    Standard Amdahl's Law models ideal parallel processing. However, in distributed
    AI clusters, scaling to dozens of nodes creates cross-switch network congestion
    during gradient AllReduce synchronization. This modified formula introduces
    an empirical super-linear network communication latency barrier (N^1.25).

BREAKDOWN OF EACH COMPONENT (WHAT DOES WHAT):
    * [Speedup(N)]: Effective acceleration factor compared to a single node.
      - VALUE: e.g., 7.26x on 8 nodes (ideal would be 8.0x).

    * [P]: Parallelizable Code Fraction.
      - WHAT IT DOES: Percentage of model operations that can run concurrently.
      - VALUE: 0.988 (98.8% of Transformer matrix multiplications are parallel).

    * [1 - P]: Sequential Serial Bottleneck.
      - WHAT IT DOES: Operations that must run serially on a single master node
        (e.g., CPU data loader batching, optimizer state steps, checkpoint writing).
      - VALUE: 1 - 0.988 = 0.012 (1.2% serial code).

    * [P / N]: Ideal Parallel Acceleration across N nodes.

    * [Comm_Penalty(N)]: Network Interconnect Barrier.
      - WHAT IT DOES: Models latency overhead of InfiniBand/RoCE AllReduce collective
        communications as node count scales across leaf-spine network switches.
      - CONSTANTS: 0.0012 coefficient with 1.25 exponent.

5.2. PARALLEL SCALING EFFICIENCY
--------------------------------------------------------------------------------
FORMULA:
    Efficiency(N) = Speedup(N) / N
    Loss_Overhead(N) = [ 1 - Efficiency(N) ] * 100%

EMPIRICAL V-GPU SCALING TABLE:
    *  1 Node ( 8 GPUs): Speedup =  1.00x | Efficiency = 100.0% | Loss =  0.0%
    *  2 Nodes (16 GPUs): Speedup =  1.96x | Efficiency =  98.2% | Loss =  1.8%
    *  4 Nodes (32 GPUs): Speedup =  3.82x | Efficiency =  95.5% | Loss =  4.5%
    *  8 Nodes (64 GPUs): Speedup =  7.26x | Efficiency =  90.7% | Loss =  9.3%
    * 16 Nodes(128 GPUs): Speedup = 13.12x | Efficiency =  82.0% | Loss = 18.0%
    * 32 Nodes(256 GPUs): Speedup = 21.84x | Efficiency =  68.3% | Loss = 31.7%
    * 64 Nodes(512 GPUs): Speedup = 31.55x | Efficiency =  49.3% | Loss = 50.7%

6.1. THERMAL MANAGEMENT & HARDWARE SAFETY GUARDRAILS
--------------------------------------------------------------------------------
[GUARDRAIL-TH-01] OPTIMAL TEMPERATURE OPERATING BAND:
    - TRIGGER CONDITION: 35.0°C <= Core_Temperature <= 68.0°C
    - ACTION: System status reports GREEN. Fan speeds operate in variable PWM mode.
      Nominal baseline WUE (0.28 L/kWh liquid / 0.45 L/kWh air) is maintained.

[GUARDRAIL-TH-02] THERMAL PENALTY COOLING BOOST:
    - TRIGGER CONDITION: Any physical GPU Core_Temperature > 70.0°C
    - ACTION: Automatic invocation of Delta_WUE = +0.05 L/kWh cooling boost.
      Secondary chiller pumps ramp up to prevent heat soak.

[GUARDRAIL-TH-03] THERMAL THROTTLING WARNING:
    - TRIGGER CONDITION: Core_Temperature > 75.0°C
    - ACTION: System status flags "any_gpu_hot = True". Scheduler limits new batch
      job admissions to reduce junction thermal density.

[GUARDRAIL-TH-04] HARDWARE OVERHEAT EMERGENCY SHUTDOWN:
    - TRIGGER CONDITION: Core_Temperature >= 85.0°C
    - ACTION: Immediate graceful abort of worker container process. Cuts vGPU
      compute allocation to protect physical silicon from permanent thermal damage.


6.2. VIRTUALIZATION & RESOURCE ISOLATION GUARDRAILS
--------------------------------------------------------------------------------
[GUARDRAIL-MEM-01] VRAM HARD CEILING ISOLATION:
    - WHAT IT ENFORCES: Enforced via Linux cgroups and container environment quotas.
    - ACTION: A tenant job is strictly isolated to its provisioned memory quota
      (e.g., 4096 MB VRAM). If a script attempts to allocate 4097 MB, the memory
      allocator throws a managed V-GPU out-of-memory error inside the container,
      completely preventing Host CUDA driver kernel panic or crashing neighbor VMs.

[GUARDRAIL-SCH-02] COMPUTE SLICING PERCENTAGE CAP:
    - WHAT IT ENFORCES: Enforced by the round-robin priority batch scheduler.
    - ACTION: Tenant jobs are capped to their allocated compute percentage (e.g., 50%).
      Prevents "noisy-neighbor" compute starvation on multi-tenant physical GPUs.

[GUARDRAIL-CLK-03] DOCKER VM CLOCK DRIFT SYNCHRONIZATION:
    - WHAT IT ENFORCES: Synchronizes host system clock to Docker Linux VM.
    - ACTION: Executes `docker run --rm --privileged alpine hwclock -s` on startup.
      Ensures container timestamps match host wall clock within <50ms.


6.3. AI SAFETY, PRIVACY & REASONING GUARDRAILS
--------------------------------------------------------------------------------
[GUARDRAIL-AI-01] 100% AIR-GAPPED ON-PREMISE PRIVACY:
    - WHAT IT ENFORCES: Complete eradication of external cloud API dependencies.
    - ACTION: All chat inference, documentation querying, and telemetry math are
      executed locally through Qwen 2.5 on `http://localhost:11434`. Zero prompts,
      code, or telemetry data ever leave the local machine.

[GUARDRAIL-AI-02] RAG SIMILARITY SCORE & HALLUCINATION SUPPRESSION:
    - WHAT IT ENFORCES: Verified citation matching in Project AI Assistant.
    - ACTION: Queries match code chunks using hybrid TF-IDF + BM25 vector search.
      If top similarity score < 0.75, the AI explicitly states:
      "I don't have information about that in this project's code, docs, or data."
      Strictly prohibits hallucinating unwritten functions or non-existent features.

[GUARDRAIL-AI-03] REAL-TIME TELEMETRY GROUNDING:
    - WHAT IT ENFORCES: Factual accuracy for all cluster status queries.
    - ACTION: Live hardware metrics (temperatures, wattages, VRAM allocations) are
      queried directly from physical drivers and injected into Qwen's system context.

[GUARDRAIL-AI-04] STEP-BY-STEP MATHEMATICAL PROOF ENFORCEMENT:
    - WHAT IT ENFORCES: Pedagogical and academic transparency.
    - ACTION: Qwen is strictly instructed to display the exact mathematical formula,
      substitute the live variables, and output the numerical derivation before
      stating the final answer.
